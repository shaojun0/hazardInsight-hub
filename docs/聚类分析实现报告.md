> 本文档说明「聚类分析」模块的实现方式、接口契约、运行与验证结果。

### 职责边界（这是本模块最重要的设计约束）

| 层 | 负责 | 明确不负责 |
| --- | --- | --- |
| 前端 | 取数、渲染、交互、错误提示、参数选择 | 不复现聚类/向量化/降维；不做键名转换 |
| FastAPI 网关 | 契约校验、上传解析、调用引擎、结果加工成前端结构 | 不实现算法、不调超参、不改簇划分 |
| cluster-engine | 向量化、特征融合、聚类、调参、降维、产物落盘 | 不感知前端页面与文案 |

**簇划分与噪声判定完全以引擎输出为准。** 网关额外计算的只有：运行统计、簇摘要（代表样本 / c-TF-IDF 关键词 / 元数据分布）、二维坐标，以及把相似度归一化到 0~1 的「置信度」（纯展示口径，接在 `Confidence` 字段上并已在 UI 标注含义）。

## 三、接口契约

### 3.1 统一响应包裹

```json
{ "success": true,  "data": { }, "error": null }
{ "success": false, "data": null, "error": { "code": "UNSUPPORTED_FILE", "message": "…", "requestId": "…", "detail": null } }
```

- `code` 为大写下划线机器码，前端可分支；`message` 是面向用户的中文描述；
- `detail` 恒为 `null`：技术细节只进服务端日志，不出网；
- `RequestValidationError` → 422 `INVALID_REQUEST`；未预期异常 → 500 `INTERNAL_ERROR`（不泄漏堆栈与路径）；
- 响应头回填 `x-request-id`，便于把用户报错与服务端日志对齐。

健康检查是唯一带顶层镜像字段的接口：`{ success, status, data: { status, service, version, engine } }`，既满足统一包裹，也方便探针直接读 `body.status`。

### 3.2 字段命名（camelCase 决策）

Python 内部一律 snake_case；对外通过 Pydantic 的 `alias_generator=to_camel` + `populate_by_name=True` 统一序列化为 camelCase，与 `shared/clustering.ts` 逐字段一致。

**为什么不用「递归改键」**：那样会连 `metadata`（如 `{"隐患级别": "A", "area_name": "1 号机组"}`）里的业务键一起改写，静默污染业务数据。别名机制只作用于**已声明的模型字段**，自由字典原样透传 —— 这一点有专门的测试守住。

副作用：请求体同时接受 camelCase 与 snake_case，便于服务端测试与前端共用同一套模型。

### 3.3 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 探针：服务 + 引擎 + 本地向量模型就绪状态 |
| `GET` | `/api/clustering/health` | 同上（同一路由二次挂载），让前端只需一条代理规则 |
| `GET` | `/api/clustering/profiles` | 20 个 profile 的算法、模型、样本上限、可用性与不可用原因；`?refresh=true` 强制重校验 |
| `GET` | `/api/clustering/algorithms` | 10 个可经 API 使用的算法及其依赖可用性 |
| `GET` | `/api/clustering/sample` | 内置示例数据（真实核电工程隐患抽样 50 条） |
| `POST` | `/api/clustering/datasets` | multipart 上传 CSV/XLSX/JSON/TXT → 解析为聚类样本 |
| `POST` | `/api/clustering/run` | 执行聚类 → 统计 + 簇摘要 + 逐条归属 + 二维坐标 |

### 3.4 上限与并发

| 约束 | 值 | 处理 |
| --- | --- | --- |
| 样本数 | ≥2 且 ≤500 | 契约层 `min_length=2`；超限 400 `TOO_MANY_ITEMS` |
| 单条文本 | ≤4000 字符 | 超长自动截断并计入 `warnings` |
| 上传文件 | ≤10 MB | 413 `FILE_TOO_LARGE` |
| 白名单后缀 | `.csv` `.xlsx` `.json` `.txt` | 其他 400 `UNSUPPORTED_FILE` |
| 墙钟超时 | 120 s | 504 `CLUSTERING_TIMEOUT` |
| 并发 | 单飞 | 同时只允许一个聚类请求，其余 429 `SERVICE_BUSY` |

单飞与超时都写在网关层，因为聚类是 CPU/内存密集型任务：宁可让后来的请求快速失败，也不要把机器打满导致全部超时。

## 四、关键实现说明

### 4.1 引擎加载与就绪状态

引擎（配置、Catalog、`ClusteringService`）在 FastAPI `lifespan` 中**后台线程预热**，并缓存本地模型校验结果（约 1.3 GB 权重的 SHA-256 校验，10 分钟 TTL）。这样：

- 首个请求不必承担磁盘校验；
- 依赖缺失/配置错误时，健康检查返回 `degraded` 与可读原因，而不是让用户对着失败的按钮猜；
- 20 个 profile 共享同一份模型校验结果（引擎自带的 `/api/v1/profiles` 每个 profile 都全量校验，较慢）。

### 4.2 一次聚类请求的完整链路

1. **准入**：样本数、ID 唯一性、文本非空与长度校验；
2. **解析 profile**：显式 `profileId` > 指定 `algorithm` 的可用 profile > 配置的默认 profile > 自动挑选（纯向量优先，再按算法偏好顺序）；
3. **超参校验**：先调引擎的 `validate_params`，参数不合法立刻 4xx，不做无谓计算；
4. **引擎聚类**：`engine.cluster(request, enforce_api_limits=True)` —— **算法结果的唯一来源**，产物由引擎自行落盘，保留可复现追溯链；
5. **复现特征**：`engine.embeddings()` 取回向量（命中引擎自有缓存则不重复推理），再用引擎的 `FeaturePipeline` 复现同一套特征变换 —— 保证后续质心/相似度计算与聚类时输入一致；
6. **二维坐标**：`DimReducer("PCA")` 降维到 2 维，**仅用于可视化**；降维失败只追加 warning，不改结果；
7. **簇摘要**：`build_digest()` 生成代表样本、c-TF-IDF 关键词、元数据分布与归一化置信度；
8. **统计**：簇数量、噪声数、最大/最小/平均簇大小、引擎耗时与网关耗时、是否命中向量缓存。

### 4.3 兜底与降级

| 场景 | 行为 |
| --- | --- |
| 关键词抽取无可用词项（语料全空白等） | 降级为空关键词，不影响聚类 |
| 未安装 jieba | 自动退化为字符 n-gram TF-IDF |
| PCA 降维失败 | 跳过散点坐标并给出 warning，结果结构仍然完整 |
| 检索增强 profile 但知识库未构建 | `profile.available=false` 并给出原因；请求时报 409 `PROFILE_UNAVAILABLE` |
| Python 服务未启动 | 前端显示「服务未就绪」并提示 `npm run dev:py`；代理层 502 转成统一错误结构 |

### 4.4 前端交互要点

- **聚类展示**：散点图支持悬停查看样本摘要，点击图例或散点高亮某个簇（其余淡化），右侧明细表同步过滤；簇卡片展示关键词、元数据分布与代表样本（可直接点开详情）；样本详情抽屉与主项目 `HazardTestDetail` 保持同一套键盘交互（Esc 关闭、遮罩关闭、Tab 焦点循环）。
- **聚类测试**：分「单次运行」与「多算法对比」两种模式；对比模式按算法逐个串行执行并给出进度，输出簇数 / 噪声数 / 引擎耗时 / 网关耗时 / 向量缓存命中情况 —— 用于判断某个算法是否在当前数据上可用，而不是只看「跑没跑通」。
- **配色**：`clusterColor(cluster_id)` 保证同一簇在散点图、图例、卡片、表格里始终同色；噪声（`-1`）固定中性灰。
- **无障碍**：图例、簇卡片、表格行均可键盘操作；簇卡片使用 `aria-pressed` 表达高亮状态。

## 五、运行方式

### 5.1 一次性准备

```bash
cd backend/python
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # Linux/macOS：.venv/bin/pip
```

> 国内网络建议加镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple`

### 5.2 日常启动

```bash
npm run dev        # 原有方式：Node API(3001) + Vite(5175)，聚类页面会提示服务未就绪
npm run dev:all    # 追加 Python 聚类服务(8000)
npm run dev:py     # 只启动 Python 聚类服务
```

跨平台启动由 `scripts/clustering/py.mjs` 负责：自动探测 `.venv/Scripts/python.exe`（Windows）或 `.venv/bin/python`（POSIX），避免把平台相关路径写进 npm script。

### 5.3 生产

```bash
npm run build      # 类型检查 + 构建
npm start          # Express 托管静态资源，并把 /api/clustering/* 反代到 Python 服务
```

目标地址由 `PY_CLUSTER_URL` 覆盖（默认 `http://127.0.0.1:8000`）。

## 七、已知限制与后续建议

1. **聚类是统计分组，不是定级结论。** 簇标签（`类别 0`、`类别 1`…）不含业务语义，需人工解读；如需业务化命名，建议引入业务词典或让模型对代表样本做命名，但应明确标注为「机器建议」。
2. **二维坐标只用于展示。** PCA 的失真在小样本/高维时较明显；如需更贴近局部结构，可切换到引擎已支持的 UMAP（当前网关只开放 PCA，因为 UMAP 首次运行需要额外编译依赖）。
3. **检索增强 profile（nr1）需要先构建知识库。** 当前示例数据直接跑 nr0 即可；如需 nr1，需按引擎文档构建 ChromaDB 知识库后再选择对应 profile。
4. **网关为单飞模式。** 若并发需求上升，建议改为进程池 + 队列，而不是放开并发（引擎的向量推理与聚类都是重内存操作）。
5. **Python 服务是独立进程。** 这带来了清晰的边界，但也意味着部署时需要同时运行两个服务；已在 README 中说明，并提供 `PY_CLUSTER_URL` 供容器编排使用。
6. **没有提交聚类结果到台账。** 「聚类展示」目前是只读分析视图；如需把簇结果回写到隐患台账/闭环流程，建议新增一个显式的「转台账」动作，而不是自动写入。

## 八、来源说明

- 聚类算法层来自既有 Python 聚类工程（`retrain-cluster`），迁移为本仓库的 `backend/python/cluster-engine`，**未重写任何算法**，其原有测试与配置一并保留；
- FastAPI 网关、契约层、前端页面与两个反向代理路径均为本次新增；
- 内置示例数据由 `backend/python/scripts/build_sample_dataset.py` 从本仓库的隐患抽样 CSV 生成（50 条，含隐患级别 / 分类 / 排查类型 / 作业区域等业务字段）。
