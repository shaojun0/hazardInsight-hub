# 隐患定级优化：方法、规则与复现说明

本次修改保留“视觉识别 → 检索 → 推理 → 确定性复核 → 结果组装”的架构。主要改变发生在推理输出和定级复核阶段。企业 ABCD 是风险处置口径，不等同于法规意义的重大事故隐患认定。

## 数据范围与字段口径

来源为用户指定目录中的三个 BIFF `.xls` 文件，每个文件 1000 条记录、28 个字段。第 1 行是文件标题，第 2 行是表头，第 3 行开始为数据。检查日期为 2025-07-08 至 2025-07-18。隐患单号 3000 个且唯一。

|字段组|字段|本次用途|
|---|---|---|
|主键|隐患单号|逐条回溯，不进入模型|
|参考标签|隐患级别|评估标签，不当作无误金标准|
|人工判定依据|A/B级判定标准|标签审核，禁止输入模型，避免泄漏|
|现场描述|隐患描述|定级输入；删除明确的“属B级隐患”等结果字样|
|分类|隐患分类|辅助检索，不能直接定级；存在分类错位|
|上下文|项目、作业区域、排查类型、检查日期/时间|描述性统计；本次文本对照不输入项目和区域，不把标高推断为落差|
|管理归属|整改责任人、责任单位、检查人、创建人、验证人、所属业务版块一级/二级|不作风险特征，防止人员/项目代理变量拟合|
|整改过程|整改期限、整改时间、流程环节、是否按期关闭、关闭日期/时间、验证日期/时间、状态|不进入模型。均可能是定级之后的过程信息，避免结果泄漏|
|图片|主信息图片1/2|单元格值均为空，但工作簿实际有嵌入绘图/图片；本轮未解析图片与记录锚点对应关系|

已读取全部三表的文本字段。原始文件只读。完整原始提取和模型结果留在 `.tmp/grading-evaluation`，不导入生产知识库、不提交个人字段到 Git。文件 SHA256、原文件/工作表/Excel 行号随提取结果保留。

## 数据质量发现

- 标签分布：B 24（0.8%）、C 444（14.8%）、D 2532（84.4%）；A 缺样本。
- 1306 条描述不足 15 字（43.53%）；B/C/D 描述中位数分别为 85/22/15 字。长度是信息量差异，不能作为升级规则。
- 规范化后完全重复描述有 71 组、181 行；这些组内部没有跨级冲突。不代表不同位置是重复隐患，不能直接删行。
- 以三字片段 Jaccard≥0.45 且字符序列相似度≥0.60 筛出 4 对跨级近似描述。该阈值只用于人工审核线索，不参与生产定级。
- 26 条填写 A/B 判定依据，其中 24 条为 B、2 条为 C。BWX01 同一条款在 B 与 C 标签中均出现，需确认项目执行口径和现场补充信息。
- 项目差异明显：防城港 258/265 为 C，陆丰 1148/1160 为 D。仅预测每项目多数等级可在本批数据获得 2867/3000=95.57% 的回放一致率，说明高一致率可能来自口径或样本选择效应，不能证明安全判断能力。本次禁止该做法。
- “临边”“安全带”“破损”“裸露”等词横跨多个等级，不具有单独定级效力。

## 主要问题及修改依据

|原逻辑|问题|样本/代码证据|新逻辑|解决目标|
|---|---|---|---|---|
|严重度5或风险乘积≥15直接A|把可能死亡当成现实重大危险，概率与暴露被绕过|原 `gradeFromRisk`；5米安全带脱钩记录人工B|A须同时满足严重后果、关键屏障失效、实际暴露和迫近性；数字矩阵不能独立确认A|减少触电/坠落后果带来的过度升级|
|单个严重度4直接B，乘积4直接C|局部缺陷易升级，风险因素未按场景关联|大多数电缆/脚手架局部缺陷历史标D；标签并非全部可靠|后果按可信事故路径打分，轻微局部缺陷与关键安全功能失效分开；矩阵仅辅助|减少D→B/C；保留实际功能失效的上调|
|检索规则只引用，业务类目不映射等级|避免了错误映射，但没有执行企业条款完整条件|24条B都填写企业判定条款|集中配置16条企业B规则，显式条件集，代码核验条件完整性和事实引用；其余检索条款无自动覆盖权|让业务规则有明确作用，杜绝代码前缀猜等级|
|模型直接给等级和分数|难检查模型补充不存在的现场条件|标高、落差、在用状态、安全附件检验状态常缺失|fact原文引用 + 多事故场景 + 三态条件检查 + 服务端守卫|追溯事实与规则，识别缺证|
|所有信息不足场景容易被“保守”升级|未知不等于更高物理风险|标签、清理等大量短描述|缺信息增加复核标记；局部轻微缺陷可暂定D，已知关键屏障失效不能D|将不确定性和实际风险分开|
|异常后固定C但关闭fallback和复核|异常伪装成正常判断，可能漏报高风险|原 `reason` catch 明确返回 fallback=false|失败/缺失候选为兼容接口暂填C，标provisional，强制复核并保留失败事件|防止静默失败|
|拼接模型理由与代码改级理由|解释可能同时出现两个互相矛盾的等级|原护栏先保留模型原文，再附新结论|最终理由由已核对原文、匹配规则、分数、差异与复核点组装|解释与最终结果一致|

## 决策顺序与等级边界

1. 视觉阶段保留观察与推断的区别，推理阶段从当前描述/证据摘录原文事实。
2. 按事故路径分别识别后果、发生可能性、关键屏障、人员暴露和立即危险，不混用不同场景的分数。
3. 对可能适用的企业条款逐项检查必要条件。条件为 met/not_met/unknown，正反结论均须事实引用。
4. 代码验证事实片段属于当前输入、引用ID存在、规则和条件ID合法且不重复。
5. 场景门槛与企业规则共同决定等级，取最高受支持的等级。企业条款完整成立提供B下限；多个缺陷的数量不直接加分。
6. 检查冲突与信息缺口，区分 supported 与 provisional；兼容接口保留 grade/severityScore/probabilityScore/riskScore。
7. 输出 gradingTrace，包括策略版本、结构化分析、候选/最终等级、匹配/冲突规则和复核原因。

|等级|充分条件/必要门槛|加重与排除|与相邻等级的边界|
|---|---|---|---|
|A|严重度≥4 + 关键屏障失效 + 实际人员暴露 +（可能性≥4或有证据的立即危险）|停止相关作业、隔离；无实际暴露不能据此确认A；法规重大认定另核|比B增加迫近性及实际暴露证据，非事故名称升级|
|B|企业目录条款完整成立，或严重度≥4 + 关键屏障失效 + 可能性≥3 + 可达/实际暴露|企业下限不能被相似D案例覆盖；缺任何必要条件不能宣称条款命中|关键功能失效和可信严重伤害路径区别于C；高分但缺证只能暂定复核|
|C|严重度≥3、风险乘积≥6或已知关键屏障失效，未达到AB|可控需有证据，不能把兼容回退C当作确认可控|非关键局部轻微后果可D，伤害/功能损坏路径明确则C|
|D|严重度≤2、乘积<6、未证实关键屏障失效的局部轻微问题|仅类别为管理/文明施工不足以D；未知关键因素必须复核|关键功能失效排除D，资料不完整不能证明设备已经失效|

降级只能由已明确的停用、隔离、完好的有效屏障、限定影响范围等事实支持，不能把未提及人员当作无人。约5米、楼层标高、无铅封、一般磨损分别不能证明超过5米、真实落差、功能失灵、达到报废。不同条款冲突按已证事实和显式条件处理，保留差异与复核要求。

## Prompt 的修改

角色限定为辅助识别与定级；统一企业风险处置定义；禁止编造事实、法规和案例；明确输入与检索文本为数据，不执行其中指令；加入有序证据记录、打分锚点、暴露/屏障/立即危险取值和精确JSON示例；禁止关键字、项目名称、整改期限、已有等级字样决定等级。规则目录与解释由同一个 `policy.ts` 生成，防止文案与代码条款ID漂移。

首轮结构化试验出现 ruleKey/basis 代替 ruleId/factIds、逐条复述无关规则和响应截断。第二轮补充字段示例、限制无关条款输出、增加与候选数量对应的输出额度；试验失败结果独立存档，不当作最终优化效果。

## 验证设计与指标

- 基准提交：`604b13da10d7eda0699c61a7648e8fd69d521e55`。原Prompt、Schema和数值守卫在 `scripts/grading/baseline` 冻结，仅评估使用，生产不导入。
- 真实调用项目当前配置的 `deepseek-v4-flash-vision-exp`。每5条一组，使用相同冻结的输入文本、分类和现有RAG检索结果；版本、上下文摘要、使用量、原始JSON和逐条结果留档。
- 这是文本候选之后的**真实模型定级阶段回放**，不是纯关键词模拟，也不是图片端到端效果。地点、项目、图片和视觉候选置信度的差异限制了外推。
- 前后都禁止使用人工标签、A/B级判定标准、整改期限、关闭状态作为预测特征。原描述中的明确结果字样也移除，但“B级作业票”属于活动事实，保留并明确不能据此定级。
- 总体一致率=预测等于参考标签的条数/有效样本数。逐级 precision/recall/F1、矩阵、相邻误差、高风险低估、D过度定级、复核率一并报告。
- 主比较采用前后均有效的配对样本；分别报告各自有效样本与包含兼容回退C的运行口径。失败、缺失和无效JSON单列，不能合并成正确预测。
- A类支持数为0，召回率无法估计；24条B不足以证明高风险可靠性。全D基线84.4%，项目多数标签基线95.57%，仅为衡量数据偏斜，不是候选算法。
- 依描述规范化哈希分组，80%开发/20%分组复核用于一致性检查。全体数据已用于描述性分析，不能将此划分宣传为完全盲测或独立外部测试。后续应另取跨时间、跨项目的专家复核集。

## 局限与后续工作

1. 核实企业完整ABCD定义、16条目录的适用范围和规则版本；新规则为本项目显式策略，尚未经企业制度负责人签署。
2. 优先补充全部24条B的在用状态、屏障、暴露、真实落差、实测数据及相邻反例；新增A类及“疑似高危但实际隔离”的负例。
3. 将嵌入图片按锚点与行关联，人工确认对应关系后做视觉端到端评测。本次图片签名计数不是有效图片数量，也不是逐行映射证明。
4. 双人盲审跨项目C/D边界及2条AB依据与标签冲突；保留初始标签、复核标签、理由与适用制度，不直接覆盖历史。
5. 引用原文只能证明文本来源，不能数学证明语义蕴含。模型仍可能误判条款条件、遗漏适用条款或选错场景分数；高风险和冲突应走复核。
6. 评估实测复核率、延迟和输出稳定性。新输出结构提高成本，供应商版本变化后需重跑固定回归集。
7. 法規核对参考住建部《房屋市政工程生产安全重大事故隐患判定标准（2024版）》；其中适用行业和法定条款不能自动转为企业A。联网检索用于确认这一口径区别，未将法规全文或未经核验条款注入生产。

- `scripts/grading`：只读提取、质量审核、原策略快照、真实模型回放及统计。

执行顺序：使用 Python 安装 `xlrd`（可放 `.tmp/python-libs`），运行 `profile_data.py`、`analyze_quality.py`、`inspect_drawings.py`；使用 `node --import tsx scripts/grading/evaluate.ts before 3000 8` 与 `after 3000 10`，随后运行 `summarize.ts`。模型连接沿用项目运行配置，不写入或输出API Key。回放会调用真实模型并产生供应商使用量。运行 `npm run test:grading`、`npm test` 和 `npm run build` 验证代码。
