# 隐患标定框单选展示与人工修正实施计划

## 一、现状与数据链路

- 页面入口为 `web/pages/Workbench.tsx`：
  - 页面级选择状态是 `activeIndex: number | null`。
  - 图片标定框点击和右侧 `HazardCard` 都通过 `hazard.index` 切换选择。
  - `updateHazard(index, patch)` 按数组下标更新隐患，人工修订通过 `patchWorkbenchResult()` 写入当前内存结果。
- 左侧图片组件为 `web/components/ImagePanel.tsx`：
  - 负责上传、重新上传、删除、AI 标注开关、说明图导出。
  - 将 `hazards`、`activeIndex` 和选择回调传给 `ImageAnnotator`。
- 标定框组件为 `web/components/ImageAnnotator.tsx`：
  - 使用 Canvas 2D 绘制图片、全部 bbox、编号、等级、类别和颜色。
  - 选中后目前只是突出当前框、降低其他框透明度，并未真正单框显示。
  - 点击事件在同一个 Canvas 内完成反向命中检测；空白点击回传 `null`。
  - 当前没有拖拽、resize、Pointer Capture 或标定框编辑能力，也没有第三方标注库。
- 右侧卡片为 `web/components/HazardCard.tsx`：
  - 卡片头部点击负责选择/取消选择；已有描述、等级、整改措施等人工编辑能力。
  - 本需求不改变卡片布局和编辑 UI。
- bbox 类型位于 `shared/types.ts`：

  ```ts
  interface BBox {
    x: number;
    y: number;
    width: number;
    height: number;
  }
  ```

  四个值均为相对原图的 `0~1` 归一化坐标，左上角为原点。`Hazard.id` 是稳定字符串，如 `H001`；`index` 仅用于展示编号。
- bbox 生成链路为：模型候选结果 → `server/lib/schema.ts` 校验 → `clampBBox()` 限制到 `0~1` 且最小宽高为 `0.02` → `Hazard.bbox` → `Workbench` → `ImagePanel` → `ImageAnnotator.drawBox()`。
- Canvas 按图片原始宽高比缩放，最长边限制为 1600；CSS 只对完整 Canvas 等比缩放，没有 `object-fit` 造成的 Canvas 内部黑边。`.image-wrap` 的黑色留白位于 Canvas 外部。
- 当前坐标换算为浏览器点击位置 → Canvas 显示矩形 → Canvas 位图坐标 → 归一化坐标。由于 bbox 本身已经归一化，编辑时可直接反算为归一化值，无需保存浏览器像素或原图像素。
- 保存策略：
  - `patchWorkbenchResult()` 只更新当前内存中的 `AnalysisResult`。
  - “保存结果”通过 `addOrMergeLastRecord()` 把完整修订结果写入浏览器 `localStorage`。
  - 报告导出直接提交当前 `AnalysisResult`。
  - 后端仅有分析和报告导出接口，没有更新 bbox 的 API；本次无需修改后端、DTO 或共享数据结构。

| `shared/types.ts`、`web/lib/workbenchSession.ts`、`web/lib/storage.ts` | bbox 类型、会话结果、显式保存 | 不增加字段、不改变持久化协议，直接复用现有能力 |
| `web/api/analysis.ts`、`server/http/analysis.routes.ts` | 分析和报告导出 | 不修改；不存在也不新增 bbox 更新 API |

内部组件接口统一为：

```ts
selectedHazardId: Hazard['id'] | null
onSelectHazard: (hazardId: Hazard['id'] | null) => void
onChangeBBox: (hazardId: Hazard['id'], bbox: BBox) => void
```

不再传递或维护 `activeIndex`、`showAllBoxes`、`currentBox` 等重复选择状态。

## 三、实施逻辑

### 1. 统一选择与显示

- `Workbench` 以 `selectedHazardId` 作为左右两侧唯一选择源。
- 图片点击 bbox 时按 `hazard.id` 选中，并滚动到对应右侧卡片。
- 点击右侧未选中卡片时切换选择；再次点击已选中卡片时设为 `null`。
- `ImageAnnotator` 只在视图层计算：

  ```ts
  const visibleHazards = selectedHazardId
    ? hazards.filter(hazard => hazard.id === selectedHazardId)
    : hazards;
  ```

- 未选择时绘制全部框；选择后只绘制当前框，并显示四个角控制点。
- 隐藏框不保留隐形命中热区。选中状态下点击当前框以外的位置按空白处理，恢复全部框；切换其他隐患使用右侧卡片。
- 新图片、删除图片、重新识别开始时立即清空选择；结果变化后若所选 ID 已不存在，也自动清空，防止继承上一任务状态。
- 保持现有编号、等级、类别、颜色、线型和 AI 标注开关语义不变。

### 2. Pointer Events 编辑

- 使用 Canvas `pointerdown / pointermove / pointerup / pointercancel`，不分别维护鼠标和触摸逻辑；Canvas 设置 `touch-action: none`。
- 未选中时按当前反向顺序命中全部可见框，重叠时仍优先最上层；首次点击只完成选择，不直接拖动。
- 已选中时优先检测四个角控制点进入 `nw/ne/se/sw` resize，命中框内部进入移动模式，命中框外取消选择。
- 开始编辑后调用 `setPointerCapture()`；移动和 resize 期间不会触发背景取消选择。
- 使用约 3 CSS px 的移动阈值区分普通点击和编辑。
- `pointermove` 只更新组件内部 draft bbox，并以 `requestAnimationFrame` 合并重绘；不在每次移动时更新页面状态或调用接口。
- `pointerup` 仅提交一次最终 bbox；`pointercancel` 回滚到编辑前位置。
- 控制点和命中半径按 CSS 像素计算，确保 Canvas 在不同响应式缩放比例下仍易于操作；鼠标光标随区域显示移动或对角 resize 形态。

### 3. 坐标反算与边界

- 每次 Pointer Event 使用 Canvas 最新的 `getBoundingClientRect()`，换算：

  ```text
  normalizedX = (clientX - rect.left) / rect.width
  normalizedY = (clientY - rect.top) / rect.height
  ```

- 编辑过程始终在归一化坐标系中计算，不能把屏幕 px 或最长边 1600 的 Canvas 位图坐标写入 `Hazard.bbox`。
- Canvas 与图片保持相同宽高比，因此无需额外 `naturalWidth/clientWidth` 比例字段；`.image-wrap` 黑边不参与坐标计算，只用于背景取消选择。
- 移动和 resize 始终满足：

  ```text
  0 <= x <= 1 - width
  0 <= y <= 1 - height
  width >= 0.02
  height >= 0.02
  x + width <= 1
  y + height <= 1
  ```

- 最小值与后端现有 `clampBBox()` 一致，确保编辑结果继续符合现有模型输出约束。

### 4. 数据同步、保存与导出

- `Workbench.updateHazard()` 改为按 `hazard.id` 执行不可变 `map` 替换，只合并目标隐患；其他 hazards 及原始数组对象不被修改。
- `onChangeBBox(id, bbox)` 复用 `patchWorkbenchResult()` 写入当前 `AnalysisResult.hazards[].bbox`。
- 项目没有 `originalBBox/manualBBox/correctedBBox` 约定，本次不扩展共享 Schema；当前结果作为可编辑工作副本。
- 拖拽提交后，即使取消选择、切换卡片或重新渲染，也继续读取修订后的 bbox。
- 未点击“保存结果”前不自动持久化；保存后完整修订结果进入本地隐患记录，重新打开记录时继续显示修订框。
- 报告导出继续使用当前修订后的 `AnalysisResult`。
- “生成隐患说明图”使用缓存图片和全部修订后的 hazards 绘制独立导出 Canvas，不受临时单框选择过滤影响，不输出 resize 控制点，并沿用当前最长边 1600 和标签开关。

## 四、测试与验收

### 自动化测试

- 新增纯函数测试，覆盖不同 CSS 显示尺寸下坐标换算、多框反向命中、隐藏框不参与命中、四角 resize、拖动边界、最小尺寸和仅更新目标 hazard。
- 执行 `npm run typecheck`、`npm test` 和 `npm run build`。
- 当前基线为 TypeScript 检查通过、36 项测试全部通过；实施后不得引入既有测试回归。

### 页面验收

1. 首次获得识别结果时显示全部 bbox。
2. 点击 bbox 1 后只显示 bbox 1，右侧卡片 1 激活并滚动到可见位置。
3. 点击右侧卡片 2 后只显示 bbox 2，卡片选中状态同步。
4. 再次点击已选中卡片或点击图片/黑色容器空白处，恢复全部 bbox。
5. 选中状态下点击隐藏框原位置按空白处理，不产生“隐形选择”。
6. 拖动当前框可改变位置，拖动期间不取消选择。
7. 四个角控制点均可改变宽高，且不能越界或缩小到 2% 以下。
8. 修改后点击空白，全部框重新出现，目标框保持修订位置，其他框完全不变。
9. 再次选择已修订隐患时显示修订值，不恢复 AI 初始值。
10. 重新上传、删除图片、重新识别或打开另一条记录时不继承旧选择。
11. 点击“保存结果”后从“隐患记录”重新打开，修订 bbox 仍然存在；未保存刷新丢失修订属于既定显式保存语义。
12. 选中单框时生成说明图，导出的 PNG 仍包含全部修订框且不含编辑控制点。
13. AI 标注开关、编号、等级、类别、颜色、右侧详情、卡片编辑、重新识别、报告导出和图片上传均保持原行为。

## 五、风险与约束

- 图片加载与 hazards 重绘必须拆分并缓存已加载图片，避免拖动时反复创建 `Image` 和解码原图。
- 图片 URL 变化时取消旧 `onload` 结果，防止上一张图片异步回写新 Canvas。
- Pointer Capture、背景取消选择和 Canvas 事件传播需要一起验证，避免拖动结束后触发空白点击。
- 导出必须使用独立绘制流程，避免把“当前仅显示一个框”或编辑控制点带入说明图。
- 不引入第三方标注库，不重新设计页面，不修改后端工作流或现有技术栈。
- 当前工作区中 `server/agent/workflows/hazard-analysis.ts` 和 `test/backend/runtime.test.ts` 已有用户修改；实施时保持这些改动不变。
