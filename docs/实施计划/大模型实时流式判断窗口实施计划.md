# 工程现场识别“大模型实时流式判断窗口”实施计划

## 一、当前代码现状判断

- 页面入口是 `web/pages/Workbench.tsx`：
  - 左侧由 `ImagePanel` 展示图片、标注和上传操作。
  - 右侧根据 `phase` 显示等待态、`AnalysisProgress`、错误态或最终 `AnalysisSummary + HazardCard`。
  - 本次保留整体双栏布局和左侧图片区，只升级右侧区域。

- 当前工作台已经是真实流式请求：
  - `web/lib/workbenchSession.ts` 的 `startWorkbenchAnalysis()` 发起分析。
  - `web/api/agent.ts` 调用 `POST /api/agent/runs/stream`。
  - 前端通过 `fetch().body.getReader()` 解析 SSE，而不是一次性等待 JSON。
  - `POST /api/analyze` 是兼容的一次性接口，但工作台目前没有使用它。

- 后端流式能力已经存在：
  - `server/http/agent.routes.ts` 持续发送 `step.*`、`tool.*`、`llm.*`、`result.completed` 等 SSE 事件。
  - `AgentRuntime` 将事件保存在 `InMemoryRunStore`。
  - `GET /api/agent/runs/:runId/events?after=N` 已支持断线和刷新后的事件回放。
  - 每个 Run 最多保存 500 个事件，最多保留 200 个 Run；服务重启后事件会丢失。

- 当前前端没有充分利用这些事件：
  - `RunViewState` 只保存 `activeStage`、`completedStages`、fallback 和复核状态。
  - `applyAgentEvent()` 没有保留日志、模型名、阶段摘要、规则命中数、风险预测或公开文本增量。
  - `AnalysisProgress` 只是进度条和普通步骤列表。
  - 完成后组件会被卸载，右侧直接切换到最终结果，因此时间线和日志不会继续展示。

- 当前领域数据位置：
  - 当前阶段：`WorkbenchSnapshot.runView`。
  - 页面状态：`WorkbenchSnapshot.phase`。
  - 最终风险：`AnalysisResult.overallRisk`。
  - 单项等级和置信度：`AnalysisResult.hazards[].grade/confidence`。
  - 规则引用：`hazards[].ruleReferences`。
  - 模型名：运行前来自 `Workbench` 的 `modelName`，运行后以 `run.started.payload.config.model` 和 `AnalysisResult.modelName` 为准。

- 当前模型 Provider 仍是非流式 Chat Completion。DeepSeek 官方接口支持 `stream:true`，并分别返回 `delta.content` 和 `delta.reasoning_content`；本方案只转发前者，后者在 Provider 层立即丢弃。[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)

## 二、推荐实现方式

采用“双层真实流式”架构：

1. Workflow 业务事件流

   继续复用现有 SSE，将真实发生的图片校验、视觉识别、知识检索、规则匹配、模型调用、确定性定级和结果组装事件转换成业务日志。不得通过前端定时器伪造分析步骤。

2. 用户可见 Token 流

   保持现有视觉和推理模型的严格 JSON 输出协议不变。确定性校验得到正式结果后，在 `assemble` 阶段增加一次短的“公开业务摘要”模型调用：

   - 输入只包含已经校验的场景、隐患、等级、置信度、规则命中和整改信息。
   - 输出为用户可见的简短中文业务摘要。
   - Provider 使用真正的 `stream:true`。
   - 仅把 `delta.content` 作为 `analysis.output.delta` 事件转发。
   - `delta.reasoning_content` 不转发、不存储、不记录日志。
   - 公开摘要不参与最终风险定级；摘要失败时仍返回正式分析结果。

### 公开接口与状态调整

- `MultimodalModelProvider` 增加：

  ```ts
  chatStream(
    system: string,
    user: string,
    options: ModelCallOptions & {
      onTextDelta(delta: string): void;
    }
  ): Promise<ModelCallResult>
  ```

- `AgentEventType` 增加：

  ```ts
  analysis.output.started
  analysis.output.delta
  analysis.output.completed
  analysis.output.failed
  ```

- Delta 事件协议：

  ```ts
  {
    channel: "public_summary",
    delta: string,
    chunkIndex: number
  }
  ```

- `RunViewState` 扩展为：

  ```ts
  {
    runId;
    status;
    modelName;
    activeStage;
    completedStages;
    progress;
    logs;
    publicOutput;
    summary: {
      scenes;
      currentGrade;
      confidence;
      ruleHits;
    };
    lastSequence;
    replayStatus;
    fallbackReason;
    requiresReview;
  }
  ```

- 日志按 `event.sequence` 去重，保证实时 SSE 与回放得到相同状态。

### Timeline 与进度

保留实际八阶段，不虚构与代码不一致的步骤：

1. 校验图片与运行配置
2. 解析图像并提取作业特征
3. 检索标准法规与历史案例
4. 匹配施工场景风险规则
5. 构建受控分析上下文
6. 调用大模型判断并生成整改建议
7. 校验隐患等级、依据与引用
8. 生成最终结果与公开摘要

进度由真实阶段事件计算：

- 已完成阶段贡献完整进度。
- 当前活动阶段只贡献半个阶段的展示进度。
- `result.completed` 后固定为 100%。
- 不使用按时间自动增长的假进度。

### 实时摘要数据口径

- 识别场景：视觉阶段已校验候选的去重 `category`，无候选时使用 `imageSummary`。
- 当前风险等级：推理阶段显示模型预测等级，校验阶段后替换为确定性最终等级。
- 置信度：候选或最终隐患中的最高 `confidence`；无候选显示 `--`。
- 规则命中数量：优先使用规则阶段的真实 `matched`；仅恢复到最终结果但事件不可用时，回退为最终结果引用的规则数。
- 不从自由文本猜测人员数量；只有后端存在明确结构化事实时才展示类似“两名人员”的日志。

## 四、UI 与数据流

数据流固定为：

```text
OpenAI-compatible Provider stream
  → 丢弃 reasoning_content
  → 合并可见 content 小片段
  → AgentRuntime 事件存储与 SSE
  → analyzeImageStream(onEvent)
  → workbenchSession 事件归约
  → AnalysisProgress 实时渲染
```

右侧面板布局：

- 顶部：
  - 动态标题：“大模型流式判断中”/“大模型判断已完成”。
  - 实际模型名。
  - `Streaming`、`Completed`、`Replaying`、`Interrupted` 状态。
  - 总体进度及进度条。

- 主体三栏：
  - 左：八阶段 Timeline。
  - 中：实时业务日志和公开 Token 输出。
  - 右：场景、等级、置信度、规则命中四项摘要。
  - 窄屏下摘要改为横向四卡并置于日志下方，不重构页面外层布局。

- 日志行为：
  - 每条日志使用后端事件真实时间。
  - 最新事件高亮。
  - 公开摘要 Delta 持续追加到同一条日志，并显示闪烁光标。
  - 用户停留在底部时自动滚动；用户主动向上查看时暂停抢滚，并显示“回到底部”。
  - 完成后移除光标，但保留全部日志和摘要。

- 底部：
  - Streaming 时显示轻量 Wave。
  - Completed 后停止动画并显示完成提示。
  - 降级或需人工复核时复用现有告警色和 `disclaimer-bar`。

- 完成与恢复：
  - `result.completed` 后 Timeline 全完成、进度 100%、状态 Completed。
  - 流式面板继续保留，正式结果展示在其下方。
  - 切换页面后由模块级会话直接恢复。
  - 浏览器刷新后，根据 `result.agentMeta.runId` 调用 events 接口回放。
  - 后端事件已过期或服务重启时，保留最终结果，并明确提示“运行轨迹已过期”，不伪造历史日志。

## 五、风险、测试与实施顺序

### 主要技术风险

- 公开摘要会增加一次模型调用和少量延迟、Token 成本：
  - 限制为约 384 输出 Token、30 秒超时和最多约 800 个可见字符。
  - 摘要失败不影响正式结果。
- 上游 Delta 可能非常碎：
  - 后端按约 50ms 或 16 个字符合并后再发事件，兼顾流畅度和 500 事件上限。
- 流式中断后不能透明重试已显示文本：
  - 首个可见 Delta 前可重试。
  - 已输出后中断则将该日志标记为 Interrupted，不拼接第二次输出。
- Prompt 注入或内容越界：
  - 公开摘要不接收原始图片、隐藏推理或完整知识文档，只接收已校验的最小结果投影。
  - React 按普通文本渲染，限制长度并移除控制字符。
- 通用 OpenAI-compatible 网关可能不支持 streaming：
  - 当前 DeepSeek 支持真实流式。
  - 其他 Provider 拒绝 streaming 时，降级为单次公开摘要并明确标记为 non-streaming，不影响主分析。
- 当前工作区已有较多未提交修改：
  - 实施时只对上述文件做增量补丁，不 reset、不覆盖现有 Workflow、reasoning effort 和 Provider 修复。

### 测试与验收

- Provider：
  - 正确解析被任意网络 chunk 拆分的 SSE。
  - 正确处理 `[DONE]`、usage、finish reason、超时和取消。
  - `reasoning_content` 从不进入回调、Runtime 事件、DOM 或 localStorage。
  - 部分输出后断线不会重复文本。

- Runtime/Workflow：
  - 八阶段事件顺序正确。
  - vision/rules/reasoning/validation 摘要字段真实可用。
  - 公开 Delta 出现在 assemble 完成之前。
  - 公开摘要失败时正式 `result.completed` 仍成功。
  - 无隐患、Mock、fallback 和人工复核路径均能完成。

- 前端状态：
  - 实时事件与完整回放归约得到相同 `RunViewState`。
  - 重复 sequence 不生成重复日志。
  - 风险预测能被最终确定性等级覆盖。
  - 完成后 100%、Completed、日志保留。
  - 刷新后可回放；事件过期时最终结果不丢失。

- UI：
  - 最新输出高亮、光标和自动滚动正常。
  - 用户向上滚动时不被强制拉回。
  - Wave 只在 Streaming 状态运动。
  - 浅色、深色主题及目标桌面分辨率正常。
  - `prefers-reduced-motion` 下关闭闪烁和 Wave 动画。

- 最终运行：
  - `npm test`
  - `npm run typecheck`
  - `npm run build`
  - `git diff --check`

### 推荐实施顺序

1. 扩展共享事件协议和 Provider 流式接口。
2. 完成 DeepSeek/OpenAI-compatible SSE 解析与安全过滤测试。
3. 增加公开摘要 Prompt、上下文和 Workflow 流式调用。
4. 丰富现有阶段事件的业务摘要字段。
5. 扩展 `RunViewState` 和事件归约、去重、回放逻辑。
6. 升级 `AnalysisProgress` 并接入完成态保留。
7. 增加样式、自动滚动和 Wave 动画。
8. 覆盖 AI、Mock、失败、刷新回放和事件过期场景，完成全量验证。
