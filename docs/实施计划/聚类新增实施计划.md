## 1. 决策与适用范围

推荐新增 **SemanticAutoKMeansStrategy：中文语义 Embedding + 有界 Auto-K + MiniBatchKMeans + 原始语义空间后处理**，算法标识建议为 `semantic_auto_kmeans`，实现版本为 `semantic-v1`。

第一阶段直接复用项目已经配置的本地 `bge-large-zh-v1.5`，通过新增 profile 启用新流程，不修改现有模型配置的编码行为。CPU 性能优化阶段对比 `bge-base-zh-v1.5`（768 维）和 `bge-small-zh-v1.5`（512 维），只有通过质量门槛才发布单独的快速 profile。本次不下载模型，也不宣称新模型已存在。模型规格、指令使用及相似度阈值须按模型校准，依据 [BGE 官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)。

选型理由：MiniBatchKMeans 的计算与内存预算比较容易限制，项目已有 sklearn、BGE、模型注册表和持久化能力；Auto-K 消除用户指定 K 的要求；语义门槛、异常检测和保守合并补足 KMeans 强制归类的缺陷。HDBSCAN 保留现有实现，并作为独立的增强候选进行对照，不成为默认主流程或每个请求都执行的前置步骤。

适用目标为 1 万～10 万条中文短文本、有限资源下自动得到可读主题。必须允许最终只有一个簇、部分噪声或全部噪声。算法不会保证对任意语料恢复唯一的“真实簇数”；有大量细粒度主题、混合主题长段落或跨领域分布偏移时，应明确报告不确定性。短文本聚类按每条输入一个主主题处理，不擅自把一条隐患拆成多条。

### 2.3 当前主要问题

1. **缺少通用自适应策略。** 现有 profile 多为历史实验固定参数，已有 HDBSCAN 不代表已经满足跨领域短文本自动聚类。
2. **语义距离口径不统一。** 当前本地模型不归一化；新方案需要独立 L2 流程，不能原地更改 normalize=false，破坏旧向量与历史结果。
3. **容量上限不是性能保证。** RADBSCAN 明确分配 N×N 布尔矩阵与距离矩阵；层次/AP 不适合作为 10 万条默认值。DBSCAN 邻域、Canopy 成对扫描、Leader 中心增长、HDBSCAN 高维退化也不能笼统保证近线性。
4. **缓存复用范围小。** 换顺序、加一条数据、跨数据集共享文本均不能部分命中现有批缓存；重复文本在首次推理中仍重复编码。
5. **网关重复工作。** 引擎完成后再次调用 embeddings、重新构建 FeaturePipeline；虽然第二次通常命中缓存，仍有读盘/校验、特征重算。summary.cache_hit 来自第二次读取，冷运行也可能被展示为“命中”。引擎 elapsed_ms 从进入 cluster() 开始计时，包含编码和特征等阶段，不能按 schema 注释理解成纯聚类算法耗时。
6. **摘要成本高。** build_digest 转 float64；逐文本把稀疏词向量 todense，再全词表排序，接近 O(NV) 遍历；每个簇重复扫描 labels 形成 O(NK) 的 Python 工作量；逐簇聚合也需要控制词表。
7. **置信度不可比。** 样本 confidence 按整批 min-max 再缩放；同一语义相似度换一批输入可能得到不同分数，全相同可能变为 0。代表文本与逐条结果使用不同映射，噪声也被计算共同质心，容易误导。
8. **可读性不足。** 当前名称“类别 N”；代表样本不去重；停用词含“未、不、无”等，若直接用于通用命名可能抹去关键否定语义。
9. **稳定性未形成完整契约。** 缺少输入规范排序、完整随机种子链、规范标签编号、命名 tie-break；固定种子不代表 CPU/GPU、不同 BLAS/依赖版本逐位相同。
10. **执行和展示需同步扩容。** 网关线程超时只停止等待；Express 把响应 arrayBuffer 全量读入内存，客户端读取完整文本再解析 JSON；散点为每点 SVG circle，并用 Math.min(...xs) 等展开参数。10 万条不能仅升级聚类算法。

## 3. 三类候选方案比较

以下为根据实现结构与算法特性的工程判断，需要第 12 节实测验证。

| 候选 | 中文语义 | 自动簇数 | 1 万～10 万性能 | 噪声/小簇 | 稳定性与主要代价 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| Embedding + MiniBatchKMeans | 主要由 Embedding 决定，通常能合并同义表达 | 本身需要 K | 固定 K/迭代/批次时容易控制；无需 N×N | 原生强制分配，不识别噪声 | 固定种子可复现，但初始中心与批次顺序敏感 | 作为快速基线，不能单独满足要求 |
| Embedding + HDBSCAN | 能识别密度结构和非球状簇；高维距离集中会影响结果 | 不要求 K，但需 min_cluster_size/min_samples | 低维有优势；高维及特定分布下可能明显退化，不能保证 10 万条服务预算 | 原生噪声、成员强度、异常分数；稀疏小主题可能全被判噪声 | 无 KMeans 式随机初始化，但仍受降维、近似 MST、并行数值和并列距离影响 | 保留密度候选，优先用于中等规模及非球状结构对照 |
| Embedding + 自适应 KMeans + 后处理 | 复用语义向量，原空间复核防止 PCA 误合并 | 服务端自动选 K，最终 K 可合并/拆分/归零 | 搜索仅在有界样本，全量只拟合一次并少量修正；预算最可解释 | 需额外设计绝对门槛、离群检测、小簇保护 | 比单次 MBK 更复杂，但随机性、工作量和输出都可版本化 | **默认推荐** |

HDBSCAN 官方明确提示维度超过约 50～100 后效果/性能可能降低；min_samples 增大会更保守并增加噪声，默认还与 min_cluster_size 关联。因此“无需 K”不等于“无需校准”。参见 [HDBSCAN FAQ](https://hdbscan.readthedocs.io/en/latest/faq.html) 与 [参数选择说明](https://hdbscan.readthedocs.io/en/latest/parameter_selection.html)。

后续公平对照应增加一个独立 `semantic_hdbscan` 候选封装，允许 PCA 50/64 维、独立 min_samples、`allow_single_cluster`、probabilities_/outlier_scores_ 诊断；保持现有 `hdbscan.py` 和 legacy profile 不变。不能直接混用两个库的 HDBSCAN 参数语义。GPU 加速优先用于 Embedding，首版不引入 RAPIDS/cuML，避免扩大 Windows 部署与复现成本。

## 4. 完整 Pipeline

```text
准入与请求指纹
→ 文本标准化/无效文本识别
→ 精确去重，记录原始 ID 与频次映射，按文本哈希排序
→ 文本级 Embedding Cache：批量查找，只编码未命中项
→ 中文 BGE Embedding → 有限值/维度/范数检查 → float32 + L2
→ 可选确定性 PCA（固定样本拟合、全量分批变换）→ 再 L2
→ 有界 Auto-K（包含 K=1 检查，不要求调用方输入 K）
→ 全量 MiniBatchKMeans → 有界局部拆分
→ 原始归一化语义空间：核心成员、异常点、边界点识别
→ 小簇保留/保守合并/噪声，最多两轮复核
→ 最终中心重算与规范 cluster_id
→ 去重代表文本、稀疏关键词、证据式中文命名
→ 成员 confidence、簇 quality_score、运行诊断
→ 扩展回所有原始 ID，真实数量和占比统计
→ 原子产物提交、分页明细、确定性抽样二维展示
```

### 4.1 标准化、无效输入和去重

- 抽出新的引擎通用规范化实现，规则版本 `zh-shorttext-v1`：NFKC、去控制字符、统一换行与连续空白、保守统一标点。网关新策略和独立引擎共用，避免重复且不一致的处理。
- 保留 negation（未/不/无/禁止等）、数字、单位、对象名称；不默认删除设备号、日期，不自动繁简转换。模板前缀剔除属于可选、版本化规则，须单独验证。
- 保留 raw_text/normalized_text/embedding_text 的区分。4000 字符的准入/展示上限与模型 512 token 截断是两回事；token 截断必须计数和告警。超过短文本范围的记录标记 long_text，首版不分段融合，以免无声改变语义。
- 上传老入口当前已经做清洗截断，无法恢复原文。新大数据上传入口保存原始 text，清洗仅由新引擎流程执行；老上传/运行链路保留原行为。
- 仅在规范化全文完全相同时合并，建立 `unique_text_key → [(original_index,id,metadata)]`。不能按前 512 token 或向量相同去重，否则长文会错误合并。哈希碰撞时核验规范化全文。
- 以 SHA-256(normalized_text UTF-8) 加全文作为排序键，不使用随机化的 Python hash()。聚类用唯一文本、默认 sample_weight=1；原始 frequency 只影响业务计数。需要频次敏感模式时另设 `min(1+log(f),5)` 权重并纳入 profile 指纹，不默认用原始频次主导主题。
- 纯空白、纯控制符、无语义乱码/纯标点进入 invalid 诊断，不参与编码；纯数字或单字不能仅因短就一概删除，要保留可配置规则。结构错误、重复 ID 仍返回明确 422。

### 4.2 Embedding 和降维

- 初次接入沿用已有 `bge-large-zh-v1.5`，在新特征阶段归一化，不改旧模型的 normalize 配置；不为对称短文本聚类默认加检索 query instruction。
- CPU 默认 FP32；GPU 可用时新编码器运行策略选择 CUDA，FP16/BF16 仅作为已校准加速模式。推理后转 float32、检查 NaN/Inf/近零范数，近零向量不能归一化后伪装正常样本。
- 默认对 U≥2000 的批次尝试 PCA 64 维；`d=min(64,D,U_fit-1)`，小批次跳过。使用随机化 SVD 时显式 random_state=42、固定 solver；只在确定性样本上拟合一次，全量复用同一变换，whiten=false，变换后再次 L2。
- PCA 仅是加速近似，不是质量保证。固定验证样本比较原空间与降维空间的近邻保持率及同义/反义对关系；达不到目标时该模型 profile 发布为 PCA128 或关闭 PCA。运行时近零投影/秩退化可回退原空间并记录原因。PCA 的 solver 与 random_state 行为见 [sklearn PCA](https://scikit-learn.org/stable/modules/generated/sklearn.decomposition.PCA.html)。
- `X_sem` 表示原始归一化语义向量，负责噪声、中心语义、命名和评分；`X_fit` 表示聚类空间，负责选 K 和快速拟合。禁止用二维展示坐标或 legacy 检索融合后的向量替代 `X_sem`。

## 5. Auto-K 与核心聚类的可执行设计

### 5.1 预算与采样

记 N 为合法结构的输入条数，U 为非空有效唯一文本数，D 为语义维度，d 为拟合维度。

| 参数 | 首版工程起点，须校准 |
| --- | --- |
| 随机种子 | 42；稳定性挑战另用 43 |
| 选 K 样本 | 总样本 `S=min(U,8192)`，按固定哈希选取；其中约 75% 训练、25% 验证，验证最多 2048 条 |
| K 上界 | `Kcap=min(256,max(1,floor(U/3)))`；还受拟合样本容量限制，候选 K≤floor(S_train/3) |
| 粗候选 | 2、4、8、16、32、64、128、256 中合法项，以及合法上界；另保留 K=1 特殊分支 |
| 细候选 | 粗最优相邻区间内至多 3 个整数点；去重后普通 K 候选总数≤12 |
| 拟合预算 | 候选 max_iter=30，batch_size=min(1024,S_train)，显式 n_init=3 |
| 最终拟合 | 单次全量 MBK，batch_size=1024 起，max_iter=100，max_no_improvement=10 |
| 全量修正 | 拆分最多 8 个父簇，每个最多一次二分；后处理最多 2 轮，最终簇数≤Kcap |

大批次用互斥训练/验证哈希桶，避免同一份数据同时选中心和评价；小批次 U<30 不做不可靠的独立留出，以留一中心诊断评估并标记 low_support。重复文本只占一个抽样名额，不允许 90% 重复行挤走长尾主题。记录样本键列表和其指纹。

均匀唯一文本采样仍可能漏掉极小主题，这是统计限制。全量分配后检查残差与小簇，并触发有界拆分；不宣称可在 10 万条中稳定发现所有只有 2 条的主题。命中 Kcap 或拆分预算时返回 `AUTO_K_CAP_REACHED` / `REFINEMENT_BUDGET_REACHED`，保留噪声而不是强行塞入大簇。

### 5.2 K=1、候选评价与确定性选择

1. U=0/1/2 按第 9 节处理。U≥3 时建立 K=1 基准中心，计算原空间留一中心相似度下分位数、固定抽样成员对相似度。仅当整批满足校准的单主题绝对门槛、无明显独立子主题证据时允许 K=1。
2. 对每个 K≥2 拟合样本 MBK，在验证集分批分配，应用与最终流程一致的轻量语义拒绝规则。不要只比较 inertia：它通常随 K 增大下降，会偏好大量小簇。
3. 使用 **中心分离代理分数**，而非冒充标准 silhouette：`a=1-cos(x,c_assigned)`，`b=1-max(cos(x,c_other))`，`p=(b-a)/max(a,b,ε)`，夹到 [-1,1]。在原空间中心上评估；小样本用 leave-one-out 防止自包含虚高。
4. 对 U≥30 的普通候选定义初始选择分数：`J=0.45*Sep+0.35*Coh+0.20*Coverage-0.15*Tiny-0.05*log(1+K)/log(1+Kcap)`。Sep/Coh 是通过绝对门槛校准到 [0,1] 的宏平均中心分离/凝聚分数；Coverage 是验证唯一文本有效归簇比例；Tiny 是落在低支持簇的验证样本比例。无合格簇的候选 J=-∞。
5. 噪声多的数据不应被 Coverage 项逼迫合并：先应用语义合格门槛，Coverage 仅在合格候选间比较。权重在开发集冻结，测试集只验收，不允许在线按结果好看程度修改。
6. 得分前两名以另一确定性样本桶重新拟合，并在共同验证集计算 ARI、噪声集合一致性；稳定性不达门槛时加诊断，不伪造“高质量”。同等得分（如差≤0.02）的合格解优先较小 K，再按固定种子和候选顺序裁决。
7. K=1 无第二中心，不套用多簇分数/轮廓系数；按单主题门槛，与可通过稳定性且明显改善凝聚/分离的多簇解比较。所有候选不合格时允许 K_final=0（全噪声），返回 `NO_COHERENT_TOPICS`。

这些权重和 0.02 是实施起点，不是通用统计定理；manifest 要记录每个候选的各分量、拒绝原因、最终选择原因。

### 5.3 全量拟合和小主题补救

- 使用最佳样本解中心初始化全量 MiniBatchKMeans，显式 `n_init=1`，固定唯一文本顺序，`reassignment_ratio=0` 起步以减少低计数中心随机迁移；空簇删除并记录，不用随机点填满 K。
- MiniBatchKMeans 的 n_init 表示试验初始化，不代表执行同等次数的完整训练；完整多次拟合的稳定性检查必须显式实现。见 [MiniBatchKMeans 官方契约](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.MiniBatchKMeans.html)。
- 单位化输入上的普通欧氏 KMeans 不严格等于 spherical KMeans，因为中心不是单位向量。首版如实命名为 MBK 初始化聚类，加最多两轮原空间余弦分配/中心更新；这些修正可能改变标签，必须重新算噪声和质量，不能声称优化同一个 KMeans 目标。
- 按原空间残差优先选最多 8 个低凝聚父簇（含一个预算内残余噪声候选桶），每个在最多 4096 条固定样本上二分，再检查全体成员。仅当两个子簇各有足够不同文本、通过绝对凝聚与分离门槛、且改善指标超过固定阈值时接受。
- 不做无界递归拆分，不把所有父簇分别跑一遍完整 Auto-K；有界补救仍不能承诺发现所有稀有主题。确有大量细小非球状主题时，应让 HDBSCAN 对照结果决定是否发布专用密度 profile。

## 6. Noise、Outlier 与小簇处理

### 6.1 语义校准与核心成员

新 profile 带 `calibration_version`，区分模型、pooling、token 截断、精度和降维口径。用开发集同义/非同义对和离群标注确定 `t_sem`（最低成员语义支持）、`t_pair`（小簇成员互相支持）、`t_merge`（合并支持）、`t_margin`（最近/次近中心间隔）。不得给全部中文模型统一硬编码“0.7 就相似”；BGE 官方也要求按实际数据分布选择阈值。

开发起点可以用 0.80/0.85 等扫描网格，但生产 profile 必须固化校准结果；没有校准产物时仅标记 experimental，质量分不可作为已验证的概率展示。换模型必须重校准。

对每个初始簇 c：

1. 按唯一文本平均得到单位中心。计算自身簇 s1、最强竞争簇 s2、margin=s1-s2；都使用 `X_sem`，中心搜索按块计算 U×K 的局部块，不创建 U×U。
2. 小簇及凝聚评分使用留一中心：总向量和减去当前唯一文本后归一化；单例没有独立支持。重复行不能充当独立证据。
3. 基于满足 `t_sem` 的成员建立临时核心；核心不足 3 个不同文本时进入小簇规则。大簇在核心余弦距离 r=1-s1 上算 median/MAD，阈值 `r_max=min(1-t_sem,median(r)+3*1.4826*MAD(r))`，MAD=0 时用校准容差替代零半径；参考成员少于 10 个时不使用不稳定的 MAD，改用绝对门槛。
4. 即使一批全无关文本的 MAD 很小，绝对门槛仍必须生效；不能仅按每簇百分位删固定 5%/10%，否则一定会把其余无关文本保留下来。
5. 大簇中心周围可能有多模态结构，再以至多 5 个核心代表锚点验证成员支持。每条仅与固定锚点比较 O(U·5·D)，不做簇内全量两两距离。

### 6.2 标签与拒绝原因

- 语义距离过远、缺乏核心支持、坏向量：标为 -1，`assignment_status=noise`，返回明确 `noise_reason`。
- s1 合格但 margin 很小：标为 `borderline`，降低 confidence；若两个目标都无稳定核心则判 ambiguous/noise。不得仅因 margin 小就一律删除同一主题内边界文本。
- 当前目标不合格而另一簇满足绝对门槛、间隔和核心支持时，可一次重分配；不能仅按“最近”就吸收噪声。
- 噪声使用统一展示桶“未归类文本”，但不是一个语义簇；无噪声质心、无语义代表、quality_score=null、confidence=null。可独立提供最多 3 条 `noise_examples`，与代表文本区分。
- invalid 文本仍保留原始 ID，cluster_id=-1、assignment_status=invalid，noise_reason 指明原因。summary.noise_count 包含所有 -1 以兼容现有约定，另有 invalid_count 子集，保证总数守恒。

### 6.3 小簇保护与合并

- 默认“小簇”指不同文本数 <5，不使用随 N 增长的比例阈值，否则 10 万条中有价值的小主题会被删除。
- 2～4 个不同文本若 pair/leave-one-out 相似度高、与其他簇有分离，则保留 `small_coherent`；支持量低导致质量分谨慎，但不能仅因小而合并。
- 单一文本重复多次可保留 `duplicate_only` 组，展示真实次数；语义质量为 null，不因重复千次得高分。孤立且不重复的单条通常为 noise；N=1 的独立输入例外见第 9 节。重复组也受主题展示容量限制，超预算保留明细及诊断，不分配到不相关簇。
- 只有小簇中心与候选目标达到 t_merge、候选锚点支持、合并后低分位凝聚不显著下降且不存在明确的否定/状态冲突证据时才能合并。否定检查只作命名和合并的保守 veto，不声称规则能覆盖所有反义表达。
- 先生成中心对候选（K≤256，可用 K×K），按相似度降序、稳定簇键升序执行；每次接受合并后重算中心与关键分位数，避免 A≈B、B≈C 引发 A 与 C 错误链式合并。
- 无合适目标的松散小簇进入噪声；保留完整合并日志。最多两轮，记录 K_selected、K_after_split、K_final，不把 Auto-K 预估值当最终簇数。

## 7. 可读结果、自动命名和质量评分

### 7.1 字段兼容与统计口径

使用“扩展字段 + 旧字段镜像”，Python/TypeScript 同步声明，避免 Pydantic response_model 丢弃新数据。示例值仅为协议示意：

```json
{
  "clusterId": 0,
  "label": "脚手架连墙件缺失",
  "clusterName": "脚手架连墙件缺失",
  "size": 120,
  "clusterSize": 120,
  "uniqueSize": 75,
  "percentage": 12.0,
  "keywords": ["脚手架", "连墙件", "缺失"],
  "representativeTexts": ["脚手架连墙件未按要求设置"],
  "representativeSamples": [
    {"id": "row-18", "text": "脚手架连墙件未按要求设置", "confidence": 0.86, "distance": 0.06}
  ],
  "qualityScore": 0.82,
  "qualityStatus": "evaluated",
  "qualityVersion": "semantic-quality-v1",
  "nameSource": "representative_phrase",
  "metadataDistribution": {}
}
```

- 内部对应 cluster_name、cluster_size、representative_texts、quality_score；HTTP 遵循现有 camelCase，不单独强推 snake_case 新接口。label=clusterName，size=clusterSize，representativeTexts 从 representativeSamples 唯一派生，避免双份结果漂移。
- cluster_size 是展开重复后的原始条数；percentage=`100*cluster_size/total_samples`，分母包含噪声/invalid。统计精确值后再四舍五入；展示总和允许舍入误差。非噪声数之和 + noise_count 必须等于 total_samples。
- summary 增加 unique_count、invalid_count、duplicate_count、coverage、noise_ratio、selected_k、final_k、quality_score、quality_version、effective_model_id、device、embedding_cache_hits/misses/hit_ratio、stage_timings、result_cache_hit、warnings。
- 所有新语义分数字段须带版本；旧 confidence 保持历史含义，新策略用已声明的 `confidenceVersion`/`distanceMetric=cosine` 指明口径，前端显示“归属可信度（启发式）”，不能把历史 min-max 分数与新分数直接排名。
- 原始中心向量、每轮候选、详细合并日志写运行产物，不发给浏览器；前端只取展示数据。

### 7.2 代表文本

按唯一文本到最终原空间中心的相似度挑选前 20 个核心候选，再按 MMR 风格依次取最多 3～5 条：优先代表性，同时与已选代表避免重复措辞。MMR 只在固定小候选集内比较；同分按 normalized_text_key、原始 ID 排序。

代表样本必须来自本簇真实输入；同一规范化文本只出现一次；原始 ID 选择确定性的最小 ID。离群/invalid 不参加代表选择。全文可从明细获取，卡片只截断展示，不截断证据本身。

### 7.3 关键词和自动命名

1. 新引擎关键词模块使用 jieba 通用中文分词与可选领域词典；词典、停用词均版本化。没有 jieba 时用有界 char n-gram 并标记 naming_degraded。保留否定短语、对象名和单位，不继承隐患专用停用词的全部内容。
2. 使用唯一文本的稀疏词频聚合。定义 `tf(t,c)=count(t,c)/sum_t count(t,c)`，`idf(t)=log(1+(C+1)/(df_cluster(t)+1))`；得分为 tf×idf，再结合代表文本覆盖率。明确这是本项目版本化的“类别词频 TF-IDF”，不是把现有文档 TF-IDF 均值改个名称。
3. 仅遍历稀疏非零项，词表上限建议 30000，短语候选/每文档特征数有上限。簇聚合用稀疏计数或 Counter，不逐行转 V 维 dense；逐条关键词优先分页时或离线批次中提取。
4. 自动名称优先从代表文本中抽取覆盖高权重关键词的连续短语，目标 6～18 个汉字；必要时用“对象 + 状态/问题”模板。通用文本不强制附加“隐患”。例如“配电箱门未上锁”“脚手架连墙件缺失”。
5. 无可靠短语时组合 2 个真实关键词；仍无关键词则使用中心样本简短片段，并标记 nameSource=fallback_text。不可凭空生成文本未支持的因果、责任、风险等级。
6. 名称冲突时加入真实区分词；仍冲突加稳定短键。名称和簇 ID 独立，重名处理不改变成员。
7. 大簇关键词需在多个不同文本中出现才优先，避免将单个边缘样本的罕见词当主题；小簇允许单条证据但显示 low_support。关键词失败只降级命名，不丢失已完成的聚类。

### 7.4 在线质量分与离线指标分离

成员 confidence 是启发式归属支持，不是概率。令 `A=clip((s1-t_sem)/(1-t_sem),0,1)`，`M=clip(margin/t_margin,0,1)`，`L` 为通过锚点/核心支持的归一分量；初始 `confidence=0.6*A+0.25*M+0.15*L`。仅单簇时 M 不可用，在剩余项间重新归一权重，记录 `single_cluster`，不能将 M 默认为 1。单例、duplicate_only 和噪声不给虚构置信度。

簇级可解释分量：

- C：唯一核心成员的原空间凝聚（均值与低分位共同考虑，映射到 [0,1]）。
- S：与其他有效簇的分离支持；K=1 时缺失。
- R：簇内通过语义/异常门槛的比例，保留后处理前分母，防止删光差样本后得满分。
- E：独立支持量 `min(1,log(1+unique_size)/log(21))`，让小簇可存在但不宣称证据充分。

初始 `quality_score=0.4*C+0.25*S+0.2*R+0.15*E`；缺失项按剩余权重归一，至少 3 个不同有效文本才产生正式分数；不足时 quality_score=null / quality_status=low_support。单簇明确标记分离不可评估。噪声、duplicate_only 不参与质量宏平均。

运行级同时展示簇质量宏平均、按原始成员加权的平均、unique coverage/noise ratio。可提供 `overall_quality=macro_quality*unique_coverage` 作为偏保守的演示摘要，但注明其受噪声比例影响；全噪声/全单例 quality=null 并说明原因，不当作系统异常。不能只展示删除噪声后的高分。

离线报告标准 ARI/NMI/AMI、B-cubed F1、配对 Precision/Recall/F1、噪声 Precision/Recall、稀有主题召回及 sampled silhouette。标准 silhouette 在标签数不满足 2≤K≤样本数−1 时不定义；只在固定样本上分块计算，不把噪声 -1 当一个普通主题。见 [sklearn silhouette_score](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.silhouette_score.html)。历史 QbEvaluator 和黄金分数保持不变，新增 evaluator。

## 8. 性能、缓存与稳定性

### 8.1 复杂度与内存预算

| 阶段 | 预算/复杂度 |
| --- | --- |
| 清洗与去重 | O(总字符数)+O(U log U) 排序；映射 O(N) |
| Embedding | 只编码 cache miss；成本由模型、token 长度、设备决定，通常是冷运行瓶颈 |
| PCA | 固定样本拟合，分批变换 O(U·D·d)；不生成 U×U |
| Auto-K | O(Σ候选 S·K·d·迭代)，候选≤12、样本≤8192；挑战拟合只针对前两名 |
| 全量 MBK | 有界批次与迭代，近似 O(U·K·d·轮次)；不能省略 K 的成本 |
| 原空间后处理 | 最坏每轮 O(U·K·D)，最多两轮；分块点乘只保留 top-2/必要候选，禁止全量 U×K×D 广播 |
| 中心关系/合并 | K≤256，允许 K×K；成员重新检查总量有轮次上限 |
| 命名/关键词 | O(非零词项数)+有界候选排序；不出现 O(N·V) dense 扫描 |
| 代表文本 | O(U·D) 中心相似度（复用后处理）+每簇≤20 候选的小规模 MMR |

10 万×1024 维 float32 约 390.6 MiB；768 维约 293 MiB；512 维约 195.3 MiB；PCA64 约 24.4 MiB。1024×256 的 float32 相似度块约 1 MiB。反之，10 万×10 万 float32 矩阵约 37.3 GiB，完全不允许进入新流程。

这些只是数组大小，不是进程峰值；模型权重、tokenizer、激活、PCA 工作空间、JSON/Python 字符串、运行产物和缓存均需计入 RSS。避免在网关再复制一次全量 float64。新流程用 contiguous float32、分批读写或 mmap，批大小同时受内存与 token 预算限制。

在线不计算完整 silhouette、不构造全量 kNN 暴力距离矩阵、不运行无界层次聚类。仅离线固定样本允许成对评价，仍分块聚合、不保留完整 N×N。ANN 是未来可选优化，不作为首版必要依赖；精确 K 中心扫描已经可控，近似索引引入后需补 recall 与稳定性验收。

### 8.2 两级 Embedding Cache 与结果缓存

保留原 `EmbeddingCache` 的目录、键格式、校验和与错误行为。新增独立 `TextEmbeddingCache`，不改变 legacy 缓存语义。

**文本键：** `SHA256(schema_version + normalized_text + preprocessing_version + model_semantic_fingerprint + encoding_runtime_fingerprint)`，使用规范 JSON 编码避免字符串拼接歧义。语义指纹包含模型文件校验和/revision、tokenizer、pooling、prompt、max_length、归一化和输出维度；运行指纹包含实际设备类别、精度、推理后端、batch/padding 策略及相关依赖版本。严格模式不跨 CPU/GPU/不同精度混用缓存；部分命中导致批次组成变化时也要测试数值一致性，不能只检查同一整批重跑。

**存储：** 新缓存子目录（运行时产物，不是业务源码）使用 SQLite 索引 + 不可变 float32 分片文件，每片例如 4096 行；索引映射 key→分片/行号/维度/校验。批量查键，编码 misses，原子完成分片后提交索引事务；索引未提交的孤立分片由维护任务回收。不能为 10 万条生成 20 万个小文件。并发写者使用 SQLite 事务和同键 single-flight；读者不能看到半写向量。

- 一级进程缓存只保存有界热点向量及分片句柄，不与模型实例缓存混为一谈；二级磁盘缓存支持跨运行/跨数据集部分复用。
- 同批重复、乱序、增加少量文本均能命中旧文本；新文本只推理一次。首次冷运行命中率依据推理前查询结果计算，不能从后续内部二次读取推导。
- 同一分片每次打开校验一次并缓存只读句柄，失效按文件属性/版本处理，避免每条文本重读整个分片。损坏分片隔离，视为 miss 重建并告警；模型不可用时必须报缺失，不能返回未验证向量。
- 模型加载失败但全部请求向量有匹配且验证通过的缓存时，允许新策略走 cache-only 完成；必须调整新 profile 可用性判定，不能先被旧 `_profile_status` 的模型检查挡住。部分 miss 无可用模型时返回 MODEL_UNAVAILABLE，不拼接替代模型向量。
- 建议按容量设 LRU/TTL（如 10 GiB/30 天起点），具体依部署磁盘确定；删除前不影响活跃任务引用。缓存权限跟随本地数据，文本哈希不等于对原始文本的匿名化保证。

**结果缓存：** 唯一文本集合 + 权重策略 + profile/代码/命名/质量/校准/运行环境指纹作为计算键；存唯一文本的标签与摘要。原始 ID、顺序、频次、metadata 变化时重新展开统计，不能直接返回旧 IDs/旧 metadata。同一次相同请求可复用展示产物，但生成新的请求追踪记录；新 run_id 不要求相同。批缓存和结果缓存使用不同命中字段。

### 8.3 CPU/GPU 与失败恢复

新编码器策略先选择实际设备再生成指纹，按 token 长度稳定分桶，CPU batch 16/32/64、GPU batch 32/64/128 做基准；恢复时还原唯一文本顺序。并发任务与 BLAS/torch 线程数统一限额，避免 n_jobs=-1 与多任务叠加。

CUDA OOM 时释放当前批次临时张量，batch 减半，有界重试直至 1；仍失败则结束 GPU 执行，将整个请求切为 CPU FP32（从 CPU 对应缓存取，剩余重算），记录 effective_device 和 fallback_reason。模型初次加载就 OOM 时直接尝试相同模型 CPU，不要指望缩 batch 解决权重装不下的问题。不能把 GPU 前半批和 CPU 后半批混为一个严格复现版本。

本地模型文件不存在/校验失败、依赖缺失：新 profile 标为不可用，返回明确错误；不自动下载，不静默换远程付费服务，不回退到 TF-IDF 假装正常完成。可用快速模型必须是预先部署且被明确选择的不同 profile。CPU 内存不足时返回资源错误而非无限重试。

GPU 半精度和 ONNX/OpenVINO 是后续加速选项，不是首版必要条件；导出/量化模型必须单独标识和做质量回归。依据 [Sentence Transformers 推理优化文档](https://sbert.net/docs/sentence_transformer/usage/efficiency.html)。

### 8.4 稳定性契约

- 固定清洗规则、唯一文本哈希序、采样、随机种子、solver、n_init、迭代/线程配置、依赖版本、模型文件、命名词典与阈值；run manifest 写完整实际值。
- 同一输入、同一版本与同一运行环境：多次冷计算也应得到相同划分；不能只靠结果缓存证明稳定。浮点临界样本记录 borderline，使用固定容差和 tie-break。
- 标签最终按成员规范化文本键集合的稳定指纹排序后编号 0..K−1，噪声固定 -1；另有 cluster_key 供内部溯源。不要按大小排序生成永久 ID，因为重复频次会改变顺序。
- 前端可以按 size 排卡片，但颜色/成员归属来自规范 ID。相同集合打乱输入顺序，ID→簇和名称应一致；新增文本不保证原簇 ID 永远不变，跨批主题追踪不属于首版承诺。
- CPU/GPU、不同线程库之间只承诺指标级一致性，并记录环境；严格演示采用固定 CPU profile 或固定设备已验证缓存，不声称跨硬件逐位复现。

### 8.5 10 万条任务执行与展示

10 万条支持不仅是修改 max_samples。新增策略的大任务建议进入有界异步 job，复用现有 SyncExecutor 的 spawn/单飞/硬超时思想，真实任务在子进程完成特征、后处理和产物，父进程只拿状态和产物引用。

- 拟新增 `POST /api/clustering/jobs`、`GET /jobs/{job_id}`、`GET /jobs/{job_id}/items?cursor=...`、`POST /jobs/{job_id}/cancel`；请求可内联 items 或引用已上传 dataset_id，二者互斥。成功提交 202，队列满 429；job 有 queued/running/completed/failed/cancelled 状态。
- 为避免浏览器完整接收再回传 10 万文本，新增 `POST /api/clustering/semantic-datasets`：保存校验后的数据集，返回 datasetId、计数、告警及最多 100 条预览。老 `/datasets` 的返回内容与行为不变。
- 建议 U 或 N>2000 使用 job，较小新请求仍可走现有 `/run`；新旧执行器共享资源准入令牌，避免旧请求和新 GPU/CPU 任务同时抢占内存。job 支持客户端轮询、去重提交/idempotency_key、崩溃后清理未完成产物；取消必须终止运行子进程并释放锁，不能仅取消协程等待。
- 运行产物先落数据再提交 manifest。分页基于冻结排序索引，不能每次读取整个巨大 JSON 后切片；summary、clusters、items 索引/分片分别存储，通过清单校验。可扩展 RunStore 的新版本旁路存储，不改旧 result/manifest 读取。
- 服务端对全体最终结果做确定性分层抽样，二维点最多 2000，优先覆盖每个有效簇和部分噪声；坐标不影响聚类，不虚造簇间分离。返回 visualizationSampleCount/totalCount/sampled，图上明确“抽样展示”。重复文本可显示重复数。
- 前端表格服务端分页/筛选，卡片摘要不依赖所有 items 已下载；独立查详情。旧小数据响应可继续内存分页。大任务禁止 10 万 SVG circle、Math.min(...10万元素)、每次状态更新全表排序。
- Express 代理支持新路径和分块/流式导出，配置显式上游连接/请求超时；长计算不占长 HTTP 等待。Vite 与生产代理分别测试，不能把 Vite 已配置 1 小时超时视为生产 fetch 也等价。

## 9. 边界情况的确定行为

| 情况 | 新策略行为 | 旧方式 |
| --- | --- | --- |
| items=[] | 明确 422 EMPTY_DATASET，不加载模型，前端空态；不产生半成品 run | 保持旧最少 2 条限制 |
| 1 条有效文本 | 成功返回 singleton：一个低支持簇、size=1、percentage=100、代表为自身；quality/confidence=null；不拟合 MBK/PCA，可无需模型 | 仍拒绝单条 |
| 2 条相同 | 精确去重为一个 duplicate_only 组，size=2；无独立语义质量分；跳过 MBK | 保持旧算法行为 |
| 2 条不同且语义相近 | 编码后以校准 pair 门槛决定同簇，标 small_coherent；质量低支持/为空 | 不更改 |
| 2 条完全无关 | 两条均为噪声，n_clusters=0；不能强制一个簇或把两个单例说成高质量簇 | 不更改 |
| 所有文本相同 | 一个 duplicate_only 组，保留全部 ID/metadata 与真实计数，跳过 PCA/Auto-K；可无需模型 | 不更改 |
| 大量重复 | 唯一文本参与拟合，原始频次展开统计；相同文本标签一致，代表去重 | 不更改 |
| 文本完全不相关 | 所有候选经过绝对语义门槛，允许全部 -1；告警“未发现可靠主题”，成功返回诊断 | 不更改 |
| 混合空白/乱码/正常文本 | 新链路将无效项标 invalid 并保留 ID，正常文本继续；全部无效则 422 NO_VALID_TEXT | 旧空白拒绝行为不变 |
| NaN/Inf/零向量 | 批量维度/行数错误直接失败；个别可定位坏向量可隔离为 invalid_embedding 并报告；大范围异常应失败而非假装全噪声 | 旧 validate_matrix 不变 |
| 模型加载失败 | 全量有效缓存可 cache-only；有 miss 则 503 MODEL_UNAVAILABLE；结构性 singleton/duplicate-only 可无需模型 | 保持旧错误语义 |
| GPU OOM | 有界缩批，再相同模型全请求 CPU 回退；仍失败明确错误 | 不改变旧编码器默认设备 |
| 仅 CPU | 正常执行 FP32、有界线程/批次；冷推理耗时单独报告 | 保持现状 |
| PCA 秩不足/投影近零 | 跳过或回退原空间，明确降维状态；不把 2D 坐标当算法输入 | 保持 legacy 错误路径 |
| 多主题长文本/截断 | 标记 long_text/truncated_token_count，保留原文；主主题聚类，评估单独统计 | 保持旧截断 |

新 schema 的放宽必须按策略分支实现：网关外层允许最少 1 条及新策略的可诊断空白项，服务解析 profile 后调用相应 validator；legacy 分支仍执行原有 min=2/nonblank 规则。独立引擎同理，不能全局放宽 validate_items 默认值来影响旧算法。空列表保持 422 即可，处理边界不等于必须返回一个空的成功簇。

## 10. 增量接入设计与具体文件清单

### 10.1 扩展契约

现有底层注册表继续只接受矩阵并返回标签。新增上层 Strategy 接收规范化文本、ID/频次映射、模型服务、缓存和 profile，返回 `SemanticRunContext`：唯一文本标签、原始/拟合特征引用、中心、成员状态、Auto-K 诊断、缓存统计、timings、摘要。矩阵只在同一子进程内传递，不作为 HTTP JSON 或全局可变 last_result 暴露。

新 `semantic_auto.py` 对外有 `fit_predict(X, **params)->labels` 适配入口，供算法发现/最小矩阵测试；同文件提供有详细结果的核心方法，供 Strategy 调用。不能为了获取诊断再次跑一遍 fit_predict。文本级去重、缓存、名称不塞进只认 X 的底层函数。

`ClusteringService.cluster()` 先按 implementation_version/algorithm 解析 Strategy：legacy-v1 走现有路径，semantic-v1 走新增 Strategy。Catalog 通过字段联合校验，只允许新版本搭配新算法和特征规范；错误组合在编码前返回 INVALID_PROFILE。列表中的 implementation_version 不能继续全部硬编码 legacy-v1。

新策略的无检索 profile 使用 `n_results=0`，不依赖 Chroma 知识库；不把历史 nr1 特征组合偷偷套入新流程。旧 ExperimentService 只处理其已有算法，新算法如不支持历史优化器应明确拒绝；后续评测走独立 benchmark，不能落入不存在的 search_space。

## 12. 测试与 Benchmark 方案

### 12.1 数据与防泄漏

- 现有 50 条样本仅作项目真实接口/展示冒烟；metadata.category 是业务层级分类，不直接等价于短文本语义金标准，不能用 grade/area 作为语义聚类输入来抬高指标。
- 后续拟新增短文本集至少覆盖隐患、客服问题、用户反馈/商品评论、一般事项等领域，建议每领域≥500 条，包含不同主题数、模板噪声、近义改写、否定对、数字单位差异、中英混合、错别字；每领域设置 2～5 条的小主题。
- 按规范化重复组、来源和模板家族切分开发/测试；近义改写的派生原文不能跨集合泄漏。质量标注由两人独立标注并仲裁，允许多主题/模糊项单独统计，不能强行当作一类。
- 1 万/5 万/10 万用独立真实或合法来源语料做性能集；精确重复率 0/30/90/99%、主题规模均衡/长尾、噪声率 0/10/30/80/100% 分层。复制 50 条到 10 万只能测试重复缓存和计数，不能证明唯一文本推理性能。
- 校准/Benchmark 产物后续放 `backend/python/cluster-engine/artifacts/` 的独立实验目录；标注数据文件路径在采集时明确登记，不声称当前 reference.json/labels.json 已可用。

### 12.2 算法对照与消融

同一模型、清洗、唯一文本、PCA、数据切分与机器下比较：

1. Embedding + MBK：K 取预登记的固定网格；若报告知道真值 K 的 oracle 结果，必须另列且注明不满足线上无 K 条件。
2. Embedding + 增强 HDBSCAN：独立 min_samples/min_cluster_size，固定相同开发集调参预算；PCA 50/64/128 或原空间单独列出。既有 legacy HDBSCAN 也保留一栏，不把其历史参数劣势当作整个候选的劣势。
3. 推荐 Auto-K + MBK + 后处理：使用冻结校准，不看测试标签选 K。
4. 消融：无去重、无逐文本缓存、无 PCA、无语义绝对门槛、无小簇合并、无局部拆分、按频次加权。记录各阶段带来的质量/时延变化，不只报告最终“最好看”的配置。

大规模 HDBSCAN/legacy 算法超过预登记时限或内存时记 timeout/OOM，不强制运行至机器失控。不能把失败样本剔除后声称算法最快。

### 12.3 指标与重复运行

每组记录 N/U、字符/token 分布、截断数、模型/文件校验、环境/设备/精度/线程、候选数/Kcap/K_final、noise/invalid/duplicate 比例、阶段耗时、CPU 峰值 RSS、GPU 峰值显存、请求/响应字节、缓存命中数。

分别测试：进程冷+模型冷+向量缓存空；模型热+向量缓存空；向量缓存全命中但结果缓存关闭；部分命中（90%旧+10%新）；完整结果缓存命中。不得把热向量缓存结果称为“Embedding 推理速度”。

语义金标准上同时报告所有样本、接受归簇样本及其 coverage；评估程序中的噪声不能当成一个共同类别把所有无关点视为正确同簇。配对指标以 contingency 计数计算，避免枚举全量 N²；B-cubed 对未分配文本按拒绝语义单独处理并说明口径。

同环境新计算至少 5 次并关闭结果缓存，另测输入 5 次乱序、重复行排列变化、种子挑战、CPU/GPU；比较 ARI、噪声一致性、ID→规范簇、代表和命名。质量/性能常规报告中位数与范围；要发布 p95，至少 20 次代表场景，不用 3 次测量声称可靠 p95。

### 12.4 必须覆盖的工程测试

- 所有第 9 节边界；精确重复文本归属一致、ID 不丢不重、计数/占比守恒、单簇分离指标缺失。

- 缓存模型/tokenizer/prompt/max_length/精度/预处理版本失效；乱序部分命中；并发同键只写完整分片；损坏、磁盘满、进程中断、索引失配不返回错向量。
- 模型缺失/校验失败、缓存全命中无模型、部分 miss 无模型、GPU 模型加载 OOM/推理 OOM/CPU 内存不足；禁止静默远程请求。

## 13. 最终验收标准

以下为拟定发布门槛，须在阶段 0 冻结硬件和测试集；若达不到，继续优化或不发布该 profile，不能把目标改写成已达成。

### 功能与兼容

- 不需要用户输入 K；可以返回 0、1 或多个有效簇，显式报告噪声和低支持小簇。
- 全部已接受输入 ID 在结果中恰好一次；精确重复归属一致；簇大小、噪声、invalid 和占比口径正确。
- 每个有效语义簇都有证据支持的名称、规模/占比、去重代表文本、关键词、质量分或明确的不可评分原因。
- 新策略通过独立 profile/Strategy 增量启用；所有旧 profile、旧缓存、旧 API 字段与旧黄金回归通过；默认选择策略不擅自迁移。
- 空数据/1～2 条/全重复/全无关/模型失败/OOM/纯 CPU 逐项有自动测试，不静默换算法或模型。

### 质量与稳定性

- 预先登记、明确单主题的中文同义配对集：合并 Precision≥0.90、Recall≥0.85；包含同对象否定/状态反转难例的错误合并率≤5%。这些门槛以人工标注粒度为准，不泛化承诺到任意中文语料。
- 独立测试集 B-cubed F1 相对同模型最强合格基线下降≤0.02，接受覆盖率下降≤5 个百分点；两者同时检查，不能通过大量拒绝获得高纯度。
- 有标注的无关/噪声集拒绝 Recall≥0.90；2～5 条真实小主题召回至少不低于固定 K MBK 基线，并单独报告最难领域失败。
- 同环境关闭结果缓存的 5 次相同/乱序运行：规范 ID→簇、名称、代表文本一致；出现浮点临界差异必须定位并修复/标记，不只报告高 ARI。
- GPU 加速 profile 相对固定 CPU FP32 参考：ARI≥0.98、噪声集合 Jaccard≥0.95（双方均无噪声定义为 1），且配对质量下降≤0.02。达不到则不发布为等价加速 profile。
- 抽查至少 100 个簇名称（不足则全查）：≥90% 可由代表文本解释且能辨认主题；无证据的风险级别、责任、因果命名为 0。

### 性能与缓存

参考环境建议固定为 8 个物理 CPU 核、32 GiB RAM、SSD；GPU 档另注明实际 GPU/显存。以下时间针对平均≤64 token、p95≤128 token、K_final≤128 的性能档，报告最大 K=256 和长文本压力档，不能混算。

| 场景 | 拟定预算 |
| --- | --- |
| 1 万唯一文本，向量缓存全命中、关闭结果缓存 | 核心选 K+聚类+后处理+摘要≤30 秒，中位数 |
| 10 万唯一文本，同上 | ≤180 秒中位数；峰值进程 RSS≤8 GiB（含已加载模型），无完整 N×N |
| 10 万条完整结果缓存，摘要/第一页 | 服务端首次可读摘要≤3 秒，明细按页读取，不包含全量下载耗时 |
| 90%旧文本+10%新文本 | 只编码未命中的唯一文本，hit/miss 与观测调用数完全一致 |
| 90%～99%精确重复 | 编码调用数=未缓存唯一文本数，结果条数仍=N |
| 仅 CPU 冷 Embedding | 基于阶段 0 实测吞吐给出 `T≈miss_unique/吞吐+其余阶段`；首次发布必须记录 1 万与10万端到端实际耗时，不承诺 BGE-large 在 CPU 上数秒完成 |
| 快速模型发布目标 | 在通过同一质量门槛时，CPU 冷端到端比 large 参考至少快 2 倍；达不到不标为快速档 |
| job 取消/硬超时 | 10 秒内释放运行资源并可接受下一任务；状态与产物一致 |

向量缓存热运行的预算不代表首次冷启动响应时间。若用户首次 10 万文本冷推理需要较长时间，job 展示阶段/进度/缓存复用效果；通过快速模型、token 长度与设备优化解决，不伪造实时完成。
